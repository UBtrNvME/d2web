## Phase 1: Source of truth

- [x] **1. Export D2's keyword table (M).** The Go build writes a JSON table of style, shape and connection keywords with value domains (enum, range, colour, boolean, text) and the painter's drawn/not-drawn flag.
  - Acceptance: JSON lists every keyword in `d2ast` reserved keywords and `d2target` shapes at the pinned commit; each entry has a domain; entries D2 validates only in code are marked and listed in the spec.
  - Verify: new Node test compares the JSON with `imports/d2`; `mise run check`.
  - Depends on: none. Files: `packages/d2web-wasm/keywords/{keywords,keywords_test}.go`, `packages/d2editor/src/keywords.json` (checked in; `UPDATE=1 go test ./keywords` rewrites it).
  - Done 4 November 2026. Deviations: the test is Go (it runs under `test:wasm`), not Node, because the probes call D2's compiler; the editor imports the checked-in JSON, so `build.mjs` is unchanged. Names and enums come from `d2ast`/`d2target`; style number ranges and booleans are validated only in `d2graph` code, so they are written in `keywords.go` and each is probed against D2 at its edges (a widened opacity range fails the test). Non-style numbers (`width`, `top`, grid) carry a minimum that D2 does not validate here. The "drawn / not drawn" flag is not in the table: it needs the painter audit, moved to task 3.
- [x] **2. `capabilities()` for shapes (M).** Pure function: fields with value, source, availability; actions from edit ops.
  - Acceptance: for shape, container, `image`, `sql_table`, code block: every advertised field changes a real compile when set; unavailable ones carry D2's reason.
  - Verify: `mise exec -- node --test packages/d2editor/tests/capabilities.test.mjs`.
  - Depends on: 1. Files: `src/capabilities.ts`, `tests/capabilities.test.mjs` (in `test:unit`), `keywords.go` (shape restrictions).
  - Done 4 November 2026. Measured against a native compile, not assumed: D2 refuses `3d` outside rectangle/square/hexagon, `double-border` outside rectangle/square/oval/circle, `multiple` on text/code/class/sql_table/image (scene builder, not the compiler), and any `font` outside its own list (`default`, `mono`). Those restrictions and the font enum are in the exported table (`only`, `not`), probed by the Go test (compiler-level) and by the Node test (full compile, every shape x every style field, plus connections). Removing `text` from `multiple`'s list fails the Node test. Fields so far: label, shape, style keywords; layout keywords (`top`, `width`, `near`, grid, `direction`) are not in `association.properties` yet, so task 4 needs either a worker addition or reading the declaration; flagged there. Actions: rename, add-child (with D2's reason), delete.

  - Done 4 November 2026. `src/inspector.ts` renders enum/boolean as selects (blank = D2's default), numbers as bounded inputs, colour/text as inputs, a Reset button when declared, and the reason under an unavailable field. Style fields other than fill/stroke/label/shape come from `capabilities()`; those four stay hand-built (their tests and colour pickers) until ported.   - Note (task 2): these keywords are absent from `association.properties`; decide first whether the worker reports them or the editor reads the source range.
  - Acceptance: each sets and resets; `top`/`left` disabled off TALA with the reason; closes the "inspector does not list top/left" gap.
  - Verify: Node test for availability; `test:editor` case.
  - Depends on: 3. Files: `src/capabilities.ts`, `src/inspector.ts`, tests.
  - Done 4 November 2026. Decision on the task 2 note: the worker reports the layout keywords (`compile/association.go` `properties()` now also emits `tooltip`, `link`, `width`, `height`, `top`, `left`, `grid-*`, `vertical-gap`, `horizontal-gap`, `direction` and `near`, under D2's keyword names; `near` has no source because D2 keeps it as a key path). This is an additive change to the association's `properties` map, not a new message. Measured against a native compile: D2 refuses `top` or `left` alone (an edit writes both through `setOps`; clearing removes both), refuses constant `near` on nested shapes, and the scene builder refuses a connection `tooltip`, so a connection advertises `link` only; every other layout keyword compiles on every shape. `top`/`left` are disabled off TALA with the reason (the TALA-only rule is ADR 0013's). `near`'s domain is D2's constants; D2 also accepts an object key there, which the inspector does not offer yet. `link` and `tooltip` sample values in tests are URLs and text. `test:editor` 29/29; `mise run check` passes.
- [x] **5. Connections (M), except direction and reverse (see 5b).** Endpoints (click selects them), direction, source and target arrowhead shape and fill, stroke fields, `animated`, reverse action.
  - Acceptance: every connection control is one edit; reverse swaps the arrow in the text; arrowhead values come from the table.
  - Verify: Node test against a compile; `test:editor` case.
  - Depends on: 2 (3 for the renderer). Files: `src/capabilities.ts`, `src/inspector.ts`, tests.
  - Done 4 November 2026 for endpoints and arrowheads. The worker now also reports `source-arrowhead`, `source-arrowhead.filled`, `target-arrowhead`, `target-arrowhead.filled` (additive `properties`, with sources, `compile/association.go` `edgeProperties`); the table gained the two arrowhead keywords (enum from `d2target.Arrowheads`). A connection shows From/To buttons that select the ends, the style fields from task 2, and both arrowheads; the Node test writes each arrowhead field through the real edit API and reads it back with its source. `test:editor` 30/30; `mise run check` passes.
- [ ] **5b. Reverse and arrow direction (S, BLOCKED: needs the user's decision).** Spec 0017 §3.5 lists a reverse action and the `->`/`<-`/`<->`/`--` direction, but §5 says "never new d2web public API in this slice", and no existing op can do either: the direction is the connection operator in the key, and the edit API (spec 0012) has `set`, `create`, `delete`, `rename`, `move` only. D2 has `d2oracle.ReconnectEdge`, which rewrites an edge's key and would give reverse; changing the operator itself has no oracle function. Options: (a) add one `reconnect` op to the edit API (public `EditOp` type, spec 0012 and protocol version question, ID-delta handling for the new edge id), (b) ship without reverse and direction (arrowhead shapes already express which end points), (c) delete and recreate the connection in the editor (loses comments, nested attributes and the key). Recommendation: (a) in its own spec, later. Until decided, the inspector shows no reverse or direction control.

  - Depends on: 3. Files: `src/capabilities.ts`, `src/inspector.ts`, tests.
  - Done 4 November 2026. Most reasons already shipped with tasks 2-4 (shape restrictions, TALA-only `top`/`left`, root-only `near`, add-child). New here: the inspector lists every action with its status (`#actions`), and a value declared in an imported file carries a note. Measured: a `set` on an imported value writes a local override (works), a `delete` of it silently changes nothing, so the field says "an edit overrides it here; Reset cannot remove it" and hides Reset; the Node test proves both halves against the real edit API. The browser test selects by focus because clicking a `sql_table` finds no `rect`/`text` node. Not verified in a browser: the imported-value note (the editor opens one file; the unit test covers `capabilities()`). `test:editor` 31/31; `mise run check` passes.
